# Security Policy

## Supported Versions

The project does not currently publish a formal version support matrix. Please report suspected vulnerabilities against the latest release or the `dev` branch. Maintainers will assess impact on other versions and determine whether fixes should be backported.

## Reporting a Vulnerability

Please do not disclose suspected vulnerabilities in public issues, discussions, or pull requests.

If the repository's **Security** tab offers **Report a vulnerability**, use that private reporting option. If it is unavailable, contact the repository maintainers privately through GitHub or the organization's established security response channel before sharing details more broadly.

Reports are most useful when they include:

- The affected version or commit and relevant environment details.
- A description of the security impact and conditions required to reproduce it.
- Minimal reproduction steps using systems and identities you are authorized to test.
- Any known mitigations or workarounds.

Do not include real private keys, PFX files or passwords, Kerberos tickets, credentials, access tokens, or unredacted production identifiers. Use synthetic or redacted data wherever possible.

The maintainers will review reports and coordinate disclosure with the reporter. Please allow time for investigation before making details public.
