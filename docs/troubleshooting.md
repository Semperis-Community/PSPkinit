# Troubleshooting

| Symptom | Likely cause |
| --- | --- |
| `KDC_ERR_PREAUTH_REQUIRED` (25) on a bare, padata-less AS-REQ | Expected — just confirms basic connectivity/parsing before you add PA-PK-AS-REQ. |
| `KDC_ERR_C_PRINCIPAL_UNKNOWN` (6) | Use `-ClientNameType 10` (NT-ENTERPRISE) with a full UPN, not a bare `sAMAccountName` with the default NT-PRINCIPAL type. |
| `KRB-ERROR 66` (`KDC_ERR_CERTIFICATE_MISMATCH`) | The KDC resolved the client principal from the SAN just fine, but rejected the certificate itself under strong mapping enforcement - almost always means the cert is missing the SID security extension. See the next row. |
| KDC rejects the certificate under strong mapping enforcement | Certificate is missing the SID security extension (`1.3.6.1.4.1.311.25.2`) — check the CA's SID-extension setting, not just the per-template `NO_SECURITY_EXTENSION` flag. If the CA won't add it, use `New-PkinitCertificateRequest -Sid` to embed it yourself (see [Advanced Usage](./advanced-usage.md#if-the-catemplate-doesnt-add-the-sid-security-extension-itself)). |
| `PSInvalidCastException`/`MethodException` mentioning `AddRange` and `Object[]` | A script function's `return $byteArray` came back as `System.Object[]` instead of the original array type (seen on Windows PowerShell 5.1) and was fed into a strict generic method like `List<byte>.AddRange`. Already patched in `Get-DR`; if you add new code with the same pattern, cast explicitly: `$list.AddRange([byte[]]$value)`. |
| `SignedCms`/`CmsSigner` type errors on Windows PowerShell 5.1 | Missing assembly load — these files already call `Add-Type -AssemblyName System.Security` (falling back to `System.Security.Cryptography.Pkcs`) at the top of `Pkinit.ps1`. |
| `New-PkinitCertificateRequest` issues a certificate, but the SAN you asked for isn't on it | The template doesn't allow enrollee-supplied SANs (Subject Name tab needs "Supply in the request", `msPKI-Certificate-Name-Flag` bit `CT_FLAG_ENROLLEE_SUPPLIES_SUBJECT`) - that's the primary mechanism this module relies on (the SAN is embedded directly as a CSR extension). If the template intentionally builds the subject from AD instead, the request also sends the SAN as a fallback attribute string (`SAN:upn=...`), but that path additionally needs the CA's `EDITF_ATTRIBUTESUBJECTALTNAME2` edit flag set: `certutil -config '<CAHostname>\<CAName>' -setreg policy\EditFlags +EDITF_ATTRIBUTESUBJECTALTNAME2`, then `Restart-Service CertSvc` on the CA. |
| `Certificate request was not issued (disposition N): ...` | Disposition 1 = general error, 2 = denied (often a template/permissions/CA-policy issue - the message text from `GetDispositionMessage()` usually says why), 5 = pending manager approval (the template requires approval - this module doesn't poll for a pending request to complete). |
| `New-PkinitCertificateRequest` throws a COM/`CreateInstance` error for `X509Enrollment.*` or `CertificateAuthority.Request` | These ProgIDs come from the CertEnroll and certcli feature that's part of Windows' certificate services client tooling. If they're missing, install the "Certificate Services Tools" / AD CS management tools for your OS, or run from a machine that already has them (e.g. a domain-joined workstation). |
| `New-PkinitCertificateRequest` throws `COMException (0x800706BA): CCertRequest::Submit: The RPC server is unavailable`, but the CA is confirmed up and `certutil -ping` works when run locally on it | RPC double-hop - you're calling this from inside a remoted session (e.g. `Invoke-Command`/WinRM) whose target isn't the CA itself, and the network-logon token can't delegate onward to the CA. Fix: run at a real console on a domain-joined machine (no remoting, no issue), or if you must remote, impersonate with real (delegatable) credentials inside the remote session first (`LogonUser` with `LOGON32_LOGON_NEW_CREDENTIALS` + `WindowsIdentity.Impersonate()`) before calling `New-PkinitCertificateRequest`. Ruling this in: TCP is reachable on both port 135 and the CA's actual dynamic RPC port, and the failure is identical whether you use the CA's FQDN or a literal IP. |
